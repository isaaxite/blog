## Meta Description 标记

下面是从 [MS Webmaster](https://www.bing.com/webmasters) 得到的提示：***缺少 Meta Description 标记***

> **问题与什么有关?**
> 页面的标头部分缺少说明。 搜索引擎可能会使用搜索引擎结果页面(SERP)中的 `<description>` 标记中所提供的描述。编写良好的描述将与页面的内容相契合，并且与搜索者的意图相关，从而帮助你提高网站流量，因为在进行搜索时，这种描述有助于提高页面的点击率。
> **如何修复?**
> 将描述添加到页面源代码的 `<head>` 部分中: `<meta name='description' content='在此处输入有关页面内容的描述性、富含关键字的文本。'>`。

出现以上提示的 2 个页面（扫描 10 个页面，其中 2 个）：

- <https://isaaxite.github.io/blog/vue-source-computed-properties-deep-dive/>
- <https://isaaxite.github.io/blog/large-number-addition/>

hexo（Next）的文章在打包后，产物中包 Meta Description 标记的方式有：

1. `<!-- more -->`，并且它前面有实际内容；
2. 有内容的 `excerpt`。

`<!-- more -->`，虽然可得产物包含 `description` 的结果，但它只是截取文章的开头，除非刻意为之，否则这段被截断的文字内容不会对整个文章有很好的概括。

提到概括的重要性，是因为 `description` 的好坏对网页 SEO 是有影响的。因此专门为 `description` 设置的 `excerpt` 显然有更加强的针对性。

## URL 路径形式

URL 的形式对 SEO 有着中等到高等程度的影响。它不像内容质量那样是决定排名的核心因素，但一个优化的 URL 能在多个方面为 SEO 带来积极影响，而一个糟糕的 URL 则可能在无形中损害你的优化努力。

反面案例：`https://isaaxite.github.io/blog/eaf706f58c36/`

### 关键词相关性

`eaf706f58c36/`：这串无意义的字母和数字组合，没有向搜索引擎传递任何关于文章主题的信息。它相当于一个没有任何标签的文件夹，搜索引擎只能依靠页面上的其他内容（如标题、正文）来判断，这无形中增加了搜索引擎理解页面的成本。

**优化后的例子**：`/blog/hexo-seo-url-optimization-guide/` 或 `/blog/understanding-sitemap-impact/`。这样的 URL 一眼就能让搜索引擎明白，这篇文章是关于“Hexo SEO URL 优化指南”的。

### 抓取效率

虽然像反面案例使用的静态 URL 很容易被抓取，但清晰、有逻辑的 URL 结构可以帮助搜索引擎更高效地理解网站的层次结构。

`.../blog/eaf7.../`：这个结构只告诉搜索引擎，内容在 `/blog/` 目录下，但后面的唯一标识符无法揭示内容分类。

**优化后的例子**：`/blog/seo/url-structure/` 这样的 URL 清晰地展示了网站的层次结构：博客 (`blog`) -> SEO 分类 (`seo`) -> 关于 URL 结构的文章 (`url-structure`)。这有助于搜索引擎建立对网站内容组织的认知。

### 如何在 Hexo 中改进

#### 修改 `_config.yml` 配置文件

找到 `permalink` 这一行，这是控制文章链接格式的关键。

```yml
# 当前可能的样子（导致你问题的配置）
# permalink: :year/:month/:day/:title/
# 或者 permalink: :id/

# 推荐修改为以下格式
# 方案A: 只包含标题（最简洁）
permalink: :title/
# 这会让链接变成 https://isaaxite.github.io/你的文章标题/

# 方案B: 保留分类和标题（结构更清晰）
# permalink: :category/:title/
# 这会让链接变成 https://isaaxite.github.io/你的分类/你的文章标题/

# 方案C: 保留博客前缀和标题（和你现有结构类似，但标题有意义）
# permalink: blog/:title/
# 这会让链接变成 https://isaaxite.github.io/blog/你的文章标题/
```

*注：`:title` 是指文件名称 (相对于 “source/_posts/“ 文件夹)。若文章本地路径是 `source/_posts/数据结构/Hash 表.md`，`:title` 将被替换为 `/数据结构/Hash 表`。参考：<https://hexo.io/docs/permalinks.html#Variables>*

#### 文章标题的拉丁化处理

修改配置后， `:title` 中含有中文，自动生成的 `URL` 会是一长串编码（如 `%E6%88%91%E7%9A%84...`），这同样不利于阅读和 SEO。

**最佳实践是**：在创建文章时，使用英文或拼音作为 `:title`。

### 标题英文 vs. 拼音

在绝大多数情况下，对于面向全球或未来的 SEO，**英文 > 拼音**。

| 特性 | 英文 (English) | 拼音 (Pinyin) |
| :--- | :--- | :--- |
| **可读性 (用户)** | **优**。任何认识拉丁字母的用户都能看懂并理解其含义（前提是英文单词正确）。例如 `docker-install-guide`，用户一看就知道是关于“Docker安装指南”的。 | **差/中**。只有懂中文发音的用户才能“读”出来，但**无法直接理解其含义**。例如 `docker-an-zhuang-zhi-nan`，懂中文的人能读出发音，但如果不读出来，很难立刻明白这是什么意思。对于完全不懂中文的海外用户，这只是一串无意义的字母。 |
| **关键词相关性 (SEO)** | **强**。URL中的英文单词是搜索引擎（尤其是Google）进行内容理解和排名的重要信号。如果你的文章是关于 "Docker Installation"，URL 中包含 `docker-install` 会非常加分。 | **弱**。<mark>搜索引擎（即使是百度）对拼音的理解能力有限。</mark>它很难将 `an-zhuang` 这个拼音与“安装”这个概念直接关联起来。因此，拼音在传递语义、增强关键词相关性方面的作用微乎其微。 |
| **美观与信任感** | **优**。专业的英文单词组成的URL显得简洁、干净，能提升网站的专业感和可信度。 | **中**。一串无分隔的拼音（如 `dockeranzhuangzhinan`）会显得很杂乱。即使加了分隔符（`docker-an-zhuang-zhi-nan`），其长度通常也比英文更长，且对于非中文读者来说，看起来会比较奇怪。 |
| **适用场景** | **广泛适用**。技术博客、面向全球的博客、希望长期发展的博客、任何不希望被语言限制的博客。 | **非常有限**。如果你的读者群体严格限定为**只懂中文的国内用户**，并且你**明确不希望吸引任何海外流量**，那么拼音是一个可选项。但即便如此，其SEO价值依然不如英文。 |

#### 为什么英文通常是更好的选择？

1. **全球化的互联网语言**：英文是互联网的通用语言。使用英文URL，你的内容对所有搜索引擎和全球用户都是友好和可理解的。这为你未来内容的传播和影响力的扩展保留了最大的可能性。
2. **最大化SEO收益**：Google等主流搜索引擎对英文关键词的识别和权重赋予是最成熟的。你在URL中使用的每一个有意义的英文单词，都是在为你页面的主题投票，告诉搜索引擎“我这一页和这个词密切相关”。这是拼音无法做到的。
3. **避免歧义和混乱**：中文有大量的同音字，一个拼音组合可能对应十几个不同的汉字。对于搜索引擎和不懂中文的用户来说，`fangwen` 到底是“访问”还是“方文”？这会造成理解上的困惑。而英文单词 `visit` 则清晰无误。

### URL 路径形式总结

- 不可使用无意义的字母和数字字符串，导致搜索引擎理解页面的成本高。清晰、有逻辑的 URL 结构才是好的组织形式。

- 避免在 URL 中出现中文字符，它会被拉丁化同样不利于阅读和 SEO。使用语义化的英文通常是更好的选择。在中文语境下，英文也比拼音更优：同音字拼音易引起歧义和混乱，搜索引擎（即使是百度）对拼音的理解能力有限。

因此，应坚定地选择使用英文作为 URL 的核心。
